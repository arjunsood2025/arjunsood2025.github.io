LLM Platform: Pretraining, Post-Training, and a From-Scratch Inference Engine

Technologies: Python, PyTorch, Triton, DDP/FSDP2, DPO, lm-eval-harness, FastAPI, Prometheus, Docker

An LLM lab runs three systems: one to pretrain a base model, one to post-train it into an assistant, and one to serve it quickly. This project builds all three, with no model, trainer, or serving framework underneath. The byte-level BPE tokenizer, the transformer itself, the distributed training loop, the preference-tuning loss, and the inference engine are all written in the repository. The model is a 125M-parameter LLaMA-style decoder-only transformer (RMSNorm, SwiGLU, RoPE, GQA, and tied embeddings), trained on 1.26B tokens of FineWeb-Edu on a single RTX 5070. It sustained 42.7% MFU, meaning it kept the GPU's arithmetic units doing useful work 42.7% of the time they theoretically could be. Checkpoint resume is bitwise-deterministic, so an interrupted run restarts into exactly the numbers an uninterrupted one would have produced.

  • Replaced two hot PyTorch operations with hand-written Triton GPU kernels: a fused RMSNorm at 2.18× and a fused cross-entropy at 3.39×, both timed on forward plus backward at real training shapes. Fusing means doing the whole operation in one pass over GPU memory instead of several, and the cross-entropy kernel computes its logsumexp online so it never has to materialize the full logit matrix. Each kernel ships with a correctness test against the PyTorch reference and a microbenchmark. The data pipeline streams memory-mapped token shards. Its MinHash deduplication and n-gram contamination filters are implemented and unit-tested, but were not applied to this particular training run.
  • Ran a seven-run scaling study over a grid of 10M, 30M, and 85M parameters with matching token budgets, then fit the compute-loss power law L = E + A·C−α, which describes how loss falls as compute rises. The fit gave α = 0.195, and a Chinchilla-style joint fit gave a data exponent of 0.323 against the paper's 0.28. Holding compute fixed, RoPE beat learned positional embeddings by 0.30 nats, while SwiGLU and GQA tied their alternatives on loss. The GQA tie is the useful result, because matching the loss with a smaller KV cache means the same quality for less memory at serving time.
  • Post-trained in two stages. First, supervised fine-tuning on 30k conversations, using loss masking so the model is scored only on its own replies and sequence packing so batches are not padded with waste. Then a from-scratch DPO implementation on 4k preference pairs, which tunes the model toward the preferred response in each pair. DPO raised preference accuracy from 42% to 58% while holding KL divergence from the starting model near 0.10, so the gain did not come from drifting far off that policy. A separate LLM judge, position-debiased and reported with bootstrap confidence intervals, nevertheless preferred the SFT model slightly: DPO won 43.8% of comparisons, with a 95% interval of [37.5, 48.8]. The number is reported as measured rather than filtered for a favorable one.
  • Built the inference engine around a paged KV cache, which stores attention state in fixed-size blocks rather than one contiguous slab per sequence, so memory is not reserved for tokens a request may never generate. Chained-hash prefix caching lets requests sharing a prompt prefix share those blocks, with copy-on-write once they diverge. Together these raised maximum concurrency from 32 sequences to 170. The engine also does continuous batching with recompute preemption, speculative decoding that accepts 53% of draft tokens for 3.09 output tokens per target forward pass at k=4, and int8 weight-only quantization. Throughput reaches 433 output tokens per second at batch 128, served over streaming SSE and instrumented with Prometheus.
  • Pinned correctness with more than 65 tests in CI, all CPU-only so the suite runs without a GPU. The load-bearing cases assert that the engine's greedy output matches the reference implementation, that paged attention matches dense SDPA even when its blocks are shuffled, that preemption cannot change output, that incremental KV-cache decoding matches a single full forward pass, and that the DPO loss matches values computed by hand.

Raft-Replicated Key-Value Store with a From-Scratch LSM Engine

Technologies: Rust, Tokio, Raft Consensus, LSM Trees, Deterministic Simulation Testing, serde/bincode

A replicated key-value database written from scratch in Rust, covering the storage engine, the consensus layer, the networking, and the test infrastructure needed to show it is correct. It is linearizable, meaning clients can never catch the cluster contradicting itself: every operation appears to take effect at one instant, in an order consistent with real time. There are no database, consensus, or RPC crates involved; the entire dependency list is tokio, serde/bincode, and crc32fast. Storage is an LSM-tree engine, with a CRC-framed write-ahead log that detects and recovers from torn writes, bloom-filtered SSTables, leveled compaction, and MVCC snapshots. Above it sits a sans-IO Raft core, meaning the consensus logic is a pure state machine that takes in messages and timer ticks and returns actions, with every socket and disk call handled outside it. That core implements pre-vote elections, pipelined replication, InstallSnapshot, membership changes, and ReadIndex.

  • Built a deterministic simulator in the style of FoundationDB. The entire cluster, including nodes, disks, network, and clients, runs single-threaded on virtual time driven by a single seeded PRNG. It injects message loss, duplication, and reordering, asymmetric partitions where one node can reach another but not the reverse, crash-restart that wipes volatile state, and forced snapshot transfers.
  • Executed 20,000 randomized failure schedules, covering roughly 420M simulated events and 17.3M client operations. Raft's own invariants, election safety, state-machine safety, and log matching, are asserted continuously, and a from-scratch Wing and Gong linearizability checker validates every client history against what a single correct server could have produced. Because a run is a pure function of its seed, any failure replays exactly.
  • Found and documented 8 real bugs, each preserved as a CI regression alongside the seed that reproduces it. The most serious was a state-machine safety violation: an InstallSnapshot covering only a prefix of the log truncated entries the follower had already acknowledged, which let a later and otherwise legitimate election overwrite an entry that was already committed. Reaching it required five rare conditions to align at a single instant, and exactly one seed in 20,000 did.
  • Shipped a production layer on a Tokio host with a single-owner event loop. Group commit batches everything drained in one pass of that loop into a single fsync, and exactly-once client sessions come from replicating a dedup table, which turns at-least-once delivery plus idempotent apply into exactly-once from the client's point of view. On a workload held at 100% reads, stale reads run at 13,517 ops/s, lease reads at 13,057 ops/s, and linearizable reads at 9,043 ops/s, so the strictest reads cost roughly 1.5× for the quorum round trip that ReadIndex requires.
  • Measured failover across 10 consecutive leader kills under a 32-connection load. Clients saw a median interruption of 2,141 ms, most of which is clients rediscovering the new leader rather than the election, which finishes in under a second. None of the 300,000 operations were lost, and full throughput returned roughly 3.5 seconds after each kill.

Quant Research Platform & C++ Event-Driven Backtesting Engine

Technologies: C++20, Python, pybind11, CMake, DuckDB, Parquet, FastAPI, Streamlit, SQLite, Docker, GitHub Actions

A research platform for market-microstructure data, built the way a production system would be. It ingests L2 order-book and trade feeds asynchronously and stores them as hive-partitioned Parquet behind a DuckDB SQL layer, which answers analytical queries 2.5 to 2.9 times faster than a pandas baseline because partition pruning and predicate pushdown let it skip the files and rows it can prove are irrelevant. On top of that sit a C++ limit-order-book replay engine, an event-driven backtester, and a statistical validation stack. The governing principle is that backtests make self-deception easy, so the platform is designed to make the honest path the default path. The included strategies exist to exercise the infrastructure, and no claim is made that they are profitable.

  • Wrote the limit-order-book replay engine in C++20, bound to Python through pybind11 with zero-copy NumPy views and the GIL released inside its hot loop, so other Python threads keep running while it works. It sustains 11.5M events per second against 23.7k for the pure-Python reference, a factor of roughly 488. A standalone C++ harness reaches 15.8M events per second, at 100 ns p50 and 200 ns p99 per apply() call.
  • Enforced bit-for-bit parity between the C++ engine and a readable pure-Python reference in CI, so a defect has to appear in two independent implementations to reach production. The synthetic simulator keeps its own copy of the order book, and tests assert that the replay engine reconstructs that exact state from the event stream alone.
  • Developed an event-driven backtester that models order latency, the market impact of walking the book, maker and taker fees, position limits, and an approximation of queue position within each L2 price level. After every run it verifies the accounting identity equity = cash + position × mid and reconciles cash against the fill log, so a bookkeeping error fails the run instead of surfacing as PnL.
  • Made leakage detection a failing test rather than a convention. Leakage is any path by which information from the future reaches a feature that is supposed to know only the past. The check is the prefix property: a feature computed on history truncated at a given time must match the same rows computed on the full history. That is verified mechanically, and the detector is itself tested against a deliberately leaky feature to confirm it catches one. Walk-forward and purged K-fold splits are verified for overlap, ordering, and purge-gap correctness.
  • Reported every metric after costs with a stationary-bootstrap confidence interval, and left no gross-PnL code path anywhere in the system, so the flattering number is not available to report by accident. The Streamlit dashboard leads with a warning whenever the Sharpe confidence interval contains zero, which is the case where the result cannot be distinguished from no edge at all. Supporting tooling includes a FastAPI service whose time-machine endpoint reconstructs the L2 book at any historical microsecond, a SQLite run registry, 55 tests, CI, and multi-stage Docker builds.

Time-Series ML Platform: Leakage-Safe Training, Evaluation, and Serving

Technologies: PyTorch (DDP, AMP), Transformers, TCNs, scikit-learn, OmegaConf, FastAPI, Prometheus, Docker, pytest

This platform provides leakage-safe training, evaluation, and serving for short-horizon prediction on noisy, regime-switching limit-order-book data. It is built as a research platform rather than a trading system, and the emphasis falls on measuring a signal honestly rather than flattering it. On this data the honest answer is that the signal does not survive transaction costs, and that a logistic regression matches the transformer. Both findings are reported up front rather than buried.

  • Built a config-driven training system covering a Transformer encoder and a TCN with multi-horizon heads, focal loss with class weighting, mixed precision, gradient accumulation, a cosine schedule with warmup, checkpointing, early stopping, and DDP through torchrun. It predicts three-class midprice direction at 1, 5, 30, and 60 second horizons, together with a forward realized-volatility bucket, from 41 causal microstructure features.
  • Enforced no-lookahead by machine check rather than by convention. Truncation invariance requires that features recomputed on data cut at time t remain bit-identical for all rows at or before t. Shuffled-label retraining must collapse to the majority-class rate. Splits carry a purge equal to the 60-second maximum label horizon plus a 60-second embargo, and the scaler and volatility-bucket edges are fit on training rows only.
  • Defended causality at the architecture level as well as in the data. The TCN normalizes per timestep instead of using GroupNorm or BatchNorm, which pool statistics across the length axis of an (N, C, L) tensor and would leak future information into the past through the normalization layer alone, a defect no amount of careful splitting would catch. A receptive-field test asserts that the output at step t is unchanged when every input after t is overwritten.
  • Traced the headline 0.899 volatility AUC to regime detection rather than skill, since it falls to between 0.281 and 0.551 within individual regimes and drops below chance where 99% accuracy comes from predicting the majority class. A transaction-cost sweep placed the Sharpe crossing zero at roughly 0.14 bps per trade, so no tradable edge survives realistic costs.
  • Identified that the project's own baseline comparison was invalid, because five-fold walk-forward results were scored against a single held-out split, which made logistic regression appear to beat the transformer at 0.769 against 0.738. A matched-split harness corrected the comparison, and on 29,774 identical test windows logistic regression ties the transformer at 0.738 AUC. Serving runs through a versioned registry with atomic promotion behind a FastAPI and Prometheus service at 1.9 ms p50 single-window CPU latency and 2,774 windows per second peak throughput at batch 64, and 43 pytest tests cover data, models, evaluation, and the API.
