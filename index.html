LLM Platform: Pretraining, Post-Training, and a From-Scratch Inference Engine

Technologies: Python, PyTorch, Triton, DDP/FSDP2, DPO, lm-eval-harness, FastAPI, Prometheus, Docker

This project implements the three systems that a modern LLM lab runs: pretraining, post-training, and high-performance serving. It uses no model, trainer, or serving frameworks. Every layer is written in the repository, including a byte-level BPE tokenizer, a LLaMA-style decoder-only transformer (RMSNorm, SwiGLU, RoPE, GQA, and tied embeddings), the distributed training loop, the DPO loss, and a paged-attention inference engine. A 125M-parameter model was trained on 1.26B tokens of FineWeb-Edu at 42.7% MFU on a single RTX 5070, with bitwise-deterministic checkpoint resume.

  • Wrote two custom Triton kernels to replace their eager PyTorch equivalents: a fused RMSNorm at 2.18× and a fused cross-entropy with online logsumexp at 3.39×, measured on forward plus backward at training shapes. Each kernel carries a PyTorch-reference correctness test and a microbenchmark. The data pipeline streams memory-mapped token shards; its MinHash deduplication and n-gram contamination filters are implemented and unit-tested, but were not applied to this particular training run.
  • Ran a seven-run scaling study across a size and token grid of 10M, 30M, and 85M parameters, fitting the compute-loss power law L = E + A·C−α at α = 0.195, with a Chinchilla joint fit giving a data exponent of 0.323 against the paper's 0.28. Matched-compute ablations showed RoPE beating learned positional embeddings by 0.30 nats, while SwiGLU and GQA tied their alternatives on loss. The GQA result is the useful one, because an equal-quality tie means the same loss at lower KV-cache cost.
  • Post-trained with SFT over 30k conversations using loss masking and sequence packing, followed by a from-scratch DPO implementation on 4k preference pairs. DPO raised preference accuracy from 42% to 58% at a controlled KL of roughly 0.10. A position-debiased LLM judge with bootstrap confidence intervals nevertheless preferred the SFT model slightly, giving DPO a win rate of 43.8% with a 95% interval of [37.5, 48.8]. The result is reported as measured rather than filtered for a favorable number.
  • Built a paged KV cache with chained-hash prefix caching and copy-on-write, raising maximum concurrency from 32 sequences to 170. The engine adds continuous batching with recompute preemption, speculative decoding that accepts 53% of draft tokens and yields 3.09 output tokens per target forward pass at k=4, and int8 weight-only quantization. Throughput reaches 433 output tokens per second at batch 128 behind a streaming SSE server instrumented with Prometheus.
  • Pinned correctness with more than 65 CPU-only tests in CI. The load-bearing cases assert that engine greedy output matches the reference implementation, that paged attention matches dense SDPA on shuffled blocks, that preemption cannot change output, that KV-cache decoding matches a full forward pass, and that the DPO loss matches hand-computed values.

Raft-Replicated Key-Value Store with a From-Scratch LSM Engine

Technologies: Rust, Tokio, Raft Consensus, LSM Trees, Deterministic Simulation Testing, serde/bincode

This project is a linearizable, replicated key-value database written from scratch in Rust, covering the storage engine, consensus, networking, and the test infrastructure needed to demonstrate correctness. It uses no database, consensus, or RPC crates; the dependency list is tokio, serde/bincode, and crc32fast. An LSM-tree engine, comprising a CRC-framed WAL with torn-write recovery, bloom-filtered SSTables, leveled compaction, and MVCC snapshots, sits beneath a sans-IO Raft core that provides pre-vote elections, pipelined replication, InstallSnapshot, membership changes, and ReadIndex.

  • Built a deterministic simulator modeled on FoundationDB, running the entire cluster, including nodes, disks, network, and clients, single-threaded on virtual time from one seeded PRNG. It injects message loss, duplication, reordering, asymmetric partitions, crash-restart with loss of volatile state, and forced snapshot transfers.
  • Executed 20,000 randomized failure schedules, covering roughly 420M simulated events and 17.3M client operations. Election safety, state-machine safety, and log matching are asserted continuously, and a from-scratch Wing and Gong linearizability checker validates every client history. Each run is a pure function of its seed, so any failure replays exactly.
  • Found and documented 8 real bugs, each with a reproducing seed preserved as a CI regression. The most serious was a state-machine safety violation in which an InstallSnapshot covering a log prefix truncated a follower's acknowledged entries, allowing a later legitimate election to overwrite a committed entry. Five rare conditions had to align at a single instant, and exactly one seed in 20,000 reached it.
  • Shipped a production layer built on a Tokio host with a single-owner event loop, group commit that batches an entire event-loop drain into one fsync, and exactly-once client sessions from replicated dedup, which combines at-least-once delivery with idempotent apply. With the workload held fixed at 100% reads, stale reads run at 13,517 ops/s, lease reads at 13,057 ops/s, and linearizable reads at 9,043 ops/s, so strict reads cost roughly 1.5× for the ReadIndex quorum round trip.
  • Measured failover across 10 consecutive leader kills under a 32-connection load. Client-observed failover took a median of 2,141 ms, a figure dominated by leader rediscovery rather than by the sub-second election itself. None of the 300,000 operations were lost, and full throughput returned roughly 3.5 seconds after each kill.

Quant Research Platform & C++ Event-Driven Backtesting Engine

Technologies: C++20, Python, pybind11, CMake, DuckDB, Parquet, FastAPI, Streamlit, SQLite, Docker, GitHub Actions

This is a production-style research platform for market-microstructure data. It ingests L2 order-book and trade feeds asynchronously, stores them as hive-partitioned Parquet behind a DuckDB SQL layer that runs analytical queries 2.5 to 2.9 times faster than a pandas baseline through partition pruning and predicate pushdown, and pairs a C++ limit-order-book replay engine with an event-driven backtester and a statistical validation stack. The governing principle is that backtests make self-deception easy, so the platform is designed to make the honest path the default path. No claim is made that the included strategies are profitable, since they exist to exercise the infrastructure.

  • Wrote a C++20 limit-order-book replay engine with zero-copy pybind11 and NumPy bindings and the GIL released in its hot loop, sustaining 11.5M events per second against 23.7k for the pure-Python reference, a factor of roughly 488. A standalone C++ harness reaches 15.8M events per second at 100 ns p50 and 200 ns p99 per apply() call.
  • Enforced bit-for-bit parity between the C++ engine and a readable pure-Python reference in CI, so a defect must appear in two independent implementations to reach production. The synthetic simulator maintains its own order book, and tests assert that the replay engine reconstructs that exact state from the event stream.
  • Developed an event-driven backtester modeling order latency, book-walking market impact, maker and taker fees, position limits, and L2 queue-position approximation. After every run it verifies the accounting identity equity = cash + position × mid and reconciles cash against the fill log.
  • Made leakage detection a failing test rather than a convention. The prefix property, which requires features computed on truncated history to match the same rows computed on full history, is checked mechanically, and the detector is itself tested against a deliberately leaky feature. Walk-forward and purged K-fold splits are verified for overlap, ordering, and purge-gap correctness.
  • Reported every metric after costs with a stationary-bootstrap confidence interval, with no gross-PnL code path anywhere in the system. The Streamlit dashboard leads with a warning whenever the Sharpe confidence interval contains zero. Supporting tooling includes a FastAPI service whose time-machine endpoint reconstructs the L2 book at any historical microsecond, a SQLite run registry, 55 tests, CI, and multi-stage Docker builds.

Time-Series ML Platform: Leakage-Safe Training, Evaluation, and Serving

Technologies: PyTorch (DDP, AMP), Transformers, TCNs, scikit-learn, OmegaConf, FastAPI, Prometheus, Docker, pytest

This platform provides leakage-safe training, evaluation, and serving for short-horizon prediction on noisy, regime-switching limit-order-book data. It is built as a research platform rather than a trading system, and the emphasis falls on measuring a signal honestly rather than flattering it. On this data the honest answer is that the signal does not survive transaction costs, and that a logistic regression matches the transformer. Both findings are reported up front rather than buried.

  • Built a config-driven training system covering a Transformer encoder and a TCN with multi-horizon heads, focal loss with class weighting, mixed precision, gradient accumulation, a cosine schedule with warmup, checkpointing, early stopping, and DDP through torchrun. It predicts three-class midprice direction at 1, 5, 30, and 60 second horizons, together with a forward realized-volatility bucket, from 41 causal microstructure features.
  • Enforced no-lookahead by machine check rather than by convention. Truncation invariance requires that features recomputed on data cut at time t remain bit-identical for all rows at or before t. Shuffled-label retraining must collapse to the majority-class rate. Splits carry a purge equal to the 60-second maximum label horizon plus a 60-second embargo, and the scaler and volatility-bucket edges are fit on training rows only.
  • Defended causality at the architecture level as well as in the data. The TCN normalizes per timestep instead of using GroupNorm or BatchNorm, which pool statistics across the length axis of an (N, C, L) tensor and would leak future information into the past through the normalization layer alone, a defect no amount of careful splitting would catch. A receptive-field test asserts that the output at step t is unchanged when every input after t is overwritten.
  • Traced the headline 0.899 volatility AUC to regime detection rather than skill, since it falls to between 0.281 and 0.551 within individual regimes and drops below chance where 99% accuracy comes from predicting the majority class. A transaction-cost sweep placed the Sharpe crossing zero at roughly 0.14 bps per trade, so no tradable edge survives realistic costs.
  • Identified that the project's own baseline comparison was invalid, because five-fold walk-forward results were scored against a single held-out split, which made logistic regression appear to beat the transformer at 0.769 against 0.738. A matched-split harness corrected the comparison, and on 29,774 identical test windows logistic regression ties the transformer at 0.738 AUC. Serving runs through a versioned registry with atomic promotion behind a FastAPI and Prometheus service at 1.9 ms p50 single-window CPU latency and 2,774 windows per second peak throughput at batch 64, and 43 pytest tests cover data, models, evaluation, and the API.
